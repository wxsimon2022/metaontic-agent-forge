# 分段方案与分镜示意图

所有新脚本及改稿在审核前都读取本文件，单段视频同样必须展示当前版镜头参考示意图；一镜到底展示关键构图与动作。拆分方案、示意图和脚本是同一版审核材料，不增加第三道确认。

## 展示顺序

1. 故事与脚本，脚本最后附“费用预估”一节，包含火山官方方案和插件方案两项金额及计费前提。
2. 多段生成时另展示分段表；单段无需拆分。分段表包含：段号、全片时间范围、生成时长、生成/续拍、主要画面与新对白、入段/出段状态、与下一段的交接及明确的过渡画面描述。
3. 确认图真实存在，直接在正文内嵌本版分镜示意图并附原图链接（不调用 present，卡片只登记最终成片）；先发出图片正文，再实际调用脚本审核提问工具。改稿影响分段、构图或交接时，更新表和图，再弹当前版审核窗口；同目录里更新的分镜图没内嵌时会被拦截。
4. 当前版通过后，单独确认制作与费用。实际视频仍每段完成先展示、等确认，再resume；示意图不能代替真实分段预览。

计划采用当前配置、模型上限、总时长和实际分段算法；可以读取插件源码中的planVideoSegments及配置核对，不因故事分镜数量增加付费调用。不要调用video_generate来试算。
单次上限内不拆生成；例如默认2.0的30秒是15+15，16秒是12+4，不能写15+1；2.5的30秒是单次生成。不支持的规格先说明，不虚构计划。
连续场景用续拍；跨地点的独立镜头先列出独立生成与剪辑方案，标清额外调用。明确“第1段预览确认后才提交第2段”，不用“全片同时生成”等表述。
费用只用可核实的实际估价，说明是估算；无法可靠估价就如实说明，不能自行编造每段金额。所有接入方式（MetaOntic Agent Forge、MetaOntic AI、火山直连）都在写脚本时一并调用只读 video_estimate，把火山官方方案和插件方案两项基础估价随脚本交付；不是脚本之前的独立步骤。是否查询账户额度与脚本估价独立，不能因接入方式跳过估价；实际按调用计费。

## 默认免费示意图

这里的“免费”仅表示不调用付费出图/视频模型；宿主对话等原有费用不在此范围。
用本地SVG/PNG画分镜构图示意，HTML可作为附加预览，不调用图片生成接口。按叙事镜头绘制主要构图，一镜到底至少一格，必要时标出关键动作变化；多段生成时每段至少一格主要画面；跨段有动作交接时，用小格或文字标注前段结束与后段起始。用简单轮廓、主体标签、道具和箭头表达位置、动作、视线与机位，不能只做几张空白文字卡。
示意图按脚本选用9:16或16:9画框；多格排版的整张画布不必与视频同画幅。主体、服装/产品、场景与光线标签保持统一。使用可读字号、清晰对比度，不引入外部脚本、字体或网络依赖。
图上注明“分镜示意，非实际生成画面”，段号、时间、当前脚本版本；不能宣称是真实成片、精确效果预览或已生成的视频帧。
写入video-projects/<slug>/storyboard-vN.svg，可附同名HTML方便打开。参考本目录segment-storyboard-example.svg的排版，按用户当前脚本重画，不能把例图冒充当前项目的图。
先检查当前项目/版本的图文件存在，再在用户可见正文内嵌图片并给原图链接，例如（路径须替换为真实文件）。分镜图是过程材料，不要调用 present——卡片只登记最终成片，提前登记会把成片挤到交付卡片后面：

```markdown
![第N版分镜示意图](</绝对路径/storyboard-vN.png>)
[打开原图](</绝对路径/storyboard-vN.png>)
```

不要把上述模板路径当成真实文件提交。SVG/HTML不能内嵌时，用已有本地渲染工具导出PNG；没有可用工具时如实说明并提供可打开的现有图文件，不付费出图或擅自安装软件。read_image等工具仅供模型检查，不能代替用户正文展示。先发含图片与打开入口的正文，再调用审核提问，禁止并行。用户说没看到图时补展示同版图，不直接继续审核，不重生成视频。
如果用户要接近成片的AI效果图，先检查实际可用出图工具并说明新增费用，得到授权后才调用；没有出图工具就说明并提供本地示意图，不承诺插件已具备文生图能力。AI效果图也不能保证视频完全一致，更不能自动作为referenceImages或首帧上传，除非制作方案明确采用并已确认。

## 例：30秒“留饭”（2.0默认15+15）

| 段 | 全片时间 / 时长 | 方式 | 内容与交接 |
| --- | --- | --- | --- |
| 1 | 0–15秒 / 15秒 | 首段生成 | 女儿回来，父亲嘴上责备却推来热饭；结尾女儿已坐下、饭盒已打开，父亲手收回 |
| 2 | 15–30秒 / 15秒 | 承接续拍 | 从打开的饭盒继续，女儿看到对面空碗，分一半饭过去；不重复进门、推饭盒或开盖，最后二人一起吃 |

下一步是展示例图后审核脚本，不是提交视频任务。此例仅展示分段方式，不包含真实报价或生成结果。

## 续拍过渡描述

分段表与示意图标出：视频1末尾/开头状态 → 过渡动作与镜头 → 新段起始状态 → 声音交接。主体标签、服装、持物手、视线和风格按实际剧情保持；切近景、中景、反应镜头要在审核前写清，不因段号自动换镜头。用具体动作的惯性承接代替空泛的“自然过渡”。每段按事件顺序组织镜头，景别、视角、运镜分别描述；镜头数量不增加付费任务。

审核后的过渡写入对应段的 `【过渡画面】单行文本`；通用延长可用 `transitionDescription`。直接称“视频1”，不写“参考视频1”。不要把当前单视频续拍描述成已有多视频的轨道补全。
