# 任务流程与测试结构整理

- `workflow/result-state.ts` 用有判别字段的状态类型统一判断生成、待查询、待交付、分段审核、部分结果与最终成果。结果文本、预览元信息、交付守卫读取相同规则，不再各自组合布尔字段。对外工具输出Schema保持兼容。
- 断点读取验证计划、完成段数、已完成任务及待查询任务的对应关系。兼容旧v1、未写version以及旧可选字段，不重写或迁移原始记录；无法恢复时停止并保留原文件。
- `workflow/segment-executor.ts` 统一原请求复用、onCreated落盘、查询、成功记录、角色图沿用、单段暂停与中断处理。生成/续拍仍各自定义请求构造、计划和前后方向游标，未改变收费审核、真人转换与单次重试边界。
- `client/progress.ts` 仅呈现实际生成进度，纯辅助函数可直接导入；`client/tool-result.ts` 在结束后切换媒体预览。删除提前返回后的完成/失败文案、详情及媒体渲染分支。
- `client/settings-actions.ts` 抽出保存、重置和控件；界面与测试调用同一入口。更新网络适配器可注入，生产沿用原有有界公开GET。
- `tests/module-test-api.mjs` 通过esbuild导入真实源码模块；移除按函数名字/缩进从成品截取执行的测试。外部依赖模拟用完整源码模块加载；整包注册、Schema、独立运行和成品安装检查继续验证构建入口。

验证：全量模拟回归、类型检查、实际Harness输出Schema、本地成品安装，以及Chrome真实组件的生成/查询/图片/完成/错误/续拍切换和历史视频播放。未调用付费API。两平台共享相同Node路径和持久化逻辑，无新平台专用命令；Windows实际桌面和文件占用场景未覆盖。

普通开发保持版本及releaseNotes不变，不创建标签或上传发行版。
