# 专业助手回传通道

## 已确认缺口

专业预设原先不装配消息工具。Harness 0.2.2 的子任务启动代码只在当前子任务作用域中找到名为 `send_message` 且带原生标记的工具时，注入父任务 ID 与回传指导。总控的前缀工具不在专业助手预设中，不能代替这项检查。

专业预设共用的插件列表现加入 report 组件，仅保留宿主原生 send_message 定义，保持工具身份、名称、参数、发送者及 signal 不变；不装配委派、列表或中断工具。总控仍用原来的平台前缀控制工具。原生消息服务继续校验父子关系；不引入自建消息队列或任务状态。

这修复了回传能力缺口，但不能凭此断定所有“协作不起来”的反馈都由该问题引起。原生宿主也会发送结束通知，缺少主动回传并不等于结束通知必定丢失。

## 验证

- 活动视频执行记录为 0；构建、类型检查、439 项自动测试与 diff 检查通过。

- Windows/macOS 共用无路径与子进程操作的模块；未做 Windows 桌面实测。
